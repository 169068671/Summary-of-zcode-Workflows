# 参考文献映射字段规范-Zcode版

## 一、定位

本规范是 [[学位论文参考文献与正文引用映射工作流]] 的**字段锁死补充**。原工作流第五节给出了字段字典但取值为示例性(含"等"字),导致不同次执行结果不可比。本规范把示例变为**固定取值清单**,确保每次分解产出的 CSV/JSON 结构一致、可汇总、可对比。

被 [[学术论文教科研数据分解工作流-Zcode版]] 阶段 3 引用。下次分解起执行本规范,既有批次保持现状不回改。

## 二、锁死项 1:citation_mode(引用方式)

固定 5 类,中文取值,不得使用英文或自造词:

| 取值 | 含义 | 判定线索 |
|---|---|---|
| 转述/概述 | 作者用自己的语言概述文献观点 | 无引号,无"引自" |
| 可能直接引语或带引号转述 | 出现引号、冒号引语或书名号且疑似原文 | 有""、""、《》且内容像原文,需原文核验 |
| 综述性并列引用 | 同一句并列多篇文献支撑同一主张 | `[2,5,8]` 或 `[2-4]` 形式 |
| 二手引用候选 | 出现"转引自""引自""某某认为"等 | 需核验是否实际引用了第三手 |
| 无法判断 | 上下文不足 | 标记后由人工抽查 |

> [!warning] 常见误判
> 带书名号《》不自动等于直接引语——书名号只说明提到了某著作,可能仍是转述。只有当引号内文字疑似原文逐字引用时,才标"可能直接引语或带引号转述"。

机器分类只作为候选标签。正式统计前,所有"可能直接引语或带引号转述"和"二手引用候选"必须人工回看核验。

## 三、锁死项 2:citation_purpose(引用用途)

固定 8 类,中文取值,每次引用只能选 1 类(取最主要用途):

| 取值 | 含义 | 判定线索 |
|---|---|---|
| 研究背景或问题提出 | 引用用于说明时代背景、问题情境 | "近年来""随着...的发展" |
| 概念界定 | 引用用于定义核心概念 | "是指""称为""叫做" |
| 研究现状或文献观点 | 引用用于综述他人研究 | "某某认为""研究表明" |
| 理论或教学模型依据 | 引用作为理论基础或模型来源 | "根据XX理论""基于XX模式" |
| 评价工具或方法依据 | 引用作为量表、公式、方法的来源 | 抽样公式、量表出处 |
| 技术背景或应用依据 | 引用说明技术事实或应用情况 | "3D打印技术可以..." |
| 政策或课程标准依据 | 引用政策文件、课程标准、法规 | 《中国制造2025》、课标 |
| 数据对照 | 引用用于与自己数据比较 | "与XX研究的结果一致" |

> [!note] 与 Codex 批次的对齐
> Codex 周宗萍批次用的是"技术背景或应用依据""研究现状或文献观点"等取值,与本规范一致。Zcode 蔡明辉批次用了"研究背景""方法来源"等,与本规范不一致——下次分解起统一用本规范取值。

## 四、锁死项 3:citation_context(引用上下文)切分规则

**默认**:取引用标记所在的完整句(从句号到句号,或从段首到句号)。

**扩展到前后句**的 5 种情况:

| 情况 | 扩展范围 | 原因 |
|---|---|---|
| 引用标记在段末,主张跨越前两句 | 向前扩展2句 | 单句不足以理解引用作用 |
| 冒号后是引语 | 包含冒号前一句+引语全文 | 引语归属需要完整 |
| 引号在上一句开始 | 包含引号开始句到引用标记句 | 直接引语需完整 |
| 连续综述由多句对应同一编号 | 包含整个综述段 | 综述性引用需完整 |
| 表格或图注中的引用 | 包含表/图标题 | 引用语境需完整 |

**不扩展**的情况:引用标记所在句本身语义完整,前后句与引用无关。

**上下文分层保存**(不得用清洗文本覆盖原始):

| 层 | 字段 | 内容 |
|---|---|---|
| 原始上下文 | `citation_context_raw`(可选) | PDF文本层直接抽取,保留断行、空格 |
| 清洗上下文 | `citation_context` | 去页眉、合并断行、修复明显空格,用于阅读 |

CSV 默认只输出 `citation_context`(清洗层)。需要原始层时在 JSON 中保留。

## 五、锁死项 4:规范化文献实体表字段

固定 5 列,字段名和顺序锁死:

| 字段名 | 含义 | 规则 |
|---|---|---|
| `entity_id` | 实体 ID,如 E001 | 去重后唯一标识 |
| `reference_labels` | 关联的文后编号 | 多个用逗号分隔,如"9,28" |
| `canonical_reference` | 规范书目 | 合并后的代表条目 |
| `dedup_basis` | 查重依据 | 独立/同一文献不同页码/同一文献不同版本/疑似重复 |
| `external_verification` | 外部核验状态 | 未核验/已由数据库核验/已由原文核验 |

> [!important] 字段名统一
> 统一用 `reference_labels`(不是 `related_labels`)。与 Codex 周宗萍批次的 3 列版本相比,本规范增加 `dedup_basis` 和 `external_verification` 两列,使查重依据可追溯。

## 六、锁死项 5:JSON 顶层结构

固定嵌套结构,顶层 5 个键:

```json

  "paper_metadata": {
    "title": "",
    "author": "",
    "institution": "",
    "degree_or_journal": "",
    "advisor_or_editor": "",
    "year": "",
    "pages": 0,
    "page_offset": 0
  },
  "summary": {
    "reference_labels": 0,
    "unique_entities": 0,
    "citation_occurrences": 0,
    "cited_labels": 0,
    "not_cited_labels": [],
    "duplicate_groups": []
  },
  "references": [
    {"label": "", "entity_id": "", "reference_text": "", "authors": "", "title": "", "document_type": "", "source_container": "", "year": ""}
  ],
  "entities": [
    {"entity_id": "", "reference_labels": "", "canonical_reference": "", "dedup_basis": "", "external_verification": ""}

  "citations": [
    {"label": "", "entity_id": "", "raw_marker": "", "pdf_page": 0, "thesis_page": 0, "section": "", "citation_context": "", "citation_mode": "", "citation_purpose": "", "mapping_confidence": ""}

```

> [!note] 与 Codex 批次的差异说明
> Codex 周宗萍批次用扁平结构(thesis/author/pdf_pages/reference_labels/...)。本规范用嵌套结构(paper_metadata/summary/references/entities/citations),更便于程序解析和字段归类。下次分解起统一用嵌套结构,既有批次保持现状。

## 七、参考文献总表字段(沿用 Codex 工作流,统一措辞)

| 字段名 | 含义 | `metadata_verification` 统一措辞 |
|---|---|---|
| `reference_label` | 文后编号 | 保留原编号 |
| `entity_id` | 实体 ID | 如 E001 |
| `reference_text` | 原始书目 | 保留原貌 |
| `authors` | 作者 | 只按可见书目提取 |
| `title` | 题名 | 不擅自补全 |
| `document_type` | J/D/M/C/A/EB 等 | 原表缺失时保持缺失 |
| `source_container` | 期刊/学校/出版社 | 不等同于外部核验 |
| `year` | 年份 | 无法判断则缺失 |
| `citation_count` | 正文引用次数 | 按出现位置计数 |
| `thesis_pages` | 论文页码 | 多页逗号分隔 |
| `mapping_status` | 映射状态 | 已匹配/未检出/无文后条目/需复核 |
| `metadata_verification` | 元数据核验状态 | **统一为"仅据论文参考文献表,未回原始来源核验"** |

> [!important] 措辞统一
> Zcode 蔡明辉批次用的是"仅据论文原表",过于简略。下次起统一用"仅据论文参考文献表,未回原始来源核验",与 Codex 批次对齐。

## 十、锁死项 6:引用内容明细 MD(人工可读引用内容清单)

> [!important] 为什么需要这个文件
> 正文引用位置 CSV 的 `citation_context` 字段是机器切分的上下文,夹杂前后句、断行、页眉,不适合直接阅读和复用。引用内容明细 MD 把每处引用整理成"引用方写的话",让用户下次可以直接使用参考文献——知道每篇文献在论文里具体被怎么引用、引用了什么内容。

### 文件名与位置

- 文件名:`论文简称_引用内容明细.md`
- 位置:`30_研究资料/03_参考文献/引用映射/`(与其他参考文献产物同目录)

### 文件最小结构(锁死)

| 章节 | 内容 |
|---|---|
| YAML frontmatter | title、record_type: citation_detail、status、created、updated、paper(双链)、source_mapping(双链)、verification_status、tags |
| 范围声明 | 明确"本文件列出引用方写的话,不是被引文献原文;被引原文核验未执行" |
| 引用方式总览 | 统计转述/直接引语候选/二手引用候选的数量,说明引用方式特点 |
| 引用内容逐条 | 按编号 [1]-[N] 顺序,每条列出:被引文献书目、位置(章节+论文页)、引用方写的话(用引用块「」或>标注) |
| 疑似错引(若有) | 单独章节列出编号错位、归属混淆、张冠李戴等问题,登记到内部不一致表 |

### 每条引用的格式(锁死)

```markdown
### [编号] 被引文献书目(作者.题名[类型].来源,年份)

- **位置**:第X章 章名 | 论文第N页
- **引用方写道**:
> 引用方在论文里写的句子,保留原文,不修改。
```

### 关键规则

1. **"引用方写的话"**指论文作者引用文献时自己写的句子(转述或提到文献时写的内容),不是被引文献原文。
2. 每条引用的话用引用块(`>`)标注,与文件正文区分,保留原文,不修改、不补全。
3. 提到著作名的引用(如"出自安德森的著作《创客:新工业革命》"),在引用方写的话里保留书名号。
4. 疑似直接引语(带引号、冒号引语)在"引用方式总览"里统计,但引用方写的话仍按原文保留,不拆分。
5. 发现编号错位、归属混淆等问题,单独列入"疑似错引"章节,并登记到 `论文简称_内部不一致.csv`。
6. 本文件是人工可读产物,机器可读数据以 JSON 和 CSV 为准;如不一致,以 CSV/JSON 为准。

### 与其他产物的关系

| 产物 | 角色 |
|---|---|
| `论文简称_正文引用位置.csv` | 机器可读,`citation_context` 字段含原始上下文 |
| `论文简称_引用内容明细.md`(本文件) | 人工可读,整理出"引用方写的话",可直接复用 |
| `论文简称_引述原文核验.csv`(可选阶段9) | 将引用方写的话与被引文献原文逐条对照 |
