# 教科研材料数据化分解工作流

> [!summary] 定位
> 本页是教科研材料的总路由。目标不是普通摘要，而是把材料拆成可追溯来源、数据资产、变量方法、主张证据链、缺口和复用方案，并建立独立复核记录。

## 一、材料分流

| 材料 | 主工作流 | 额外要求 |
|---|---|---|
| 学术文章、期刊论文、硕博论文 | [[学术论文教科研数据分解工作流-Zcode版]] | 参考文献映射按[[学位论文参考文献与正文引用映射工作流]]执行，字段按[[参考文献映射字段规范-Zcode版]]锁死 |
| 教案、课件、学习单、试卷、量规 | 目标—活动—评价—证据分解 | 区分设计数据、预期数据和课堂真实数据 |
| 课题申报、中期、结题与附件 | 多文件版本与证据链审计 | 核对申报目标、过程记录、原始数据和结论一致性 |
| 政策、同行案例、教研材料 | 来源与用途分解 | 不把政策观点或案例叙述当作实证数据 |

项目库内存在更具体的本地工作流时，先读取项目 `AGENTS.md` 和该工作流；本页负责跨项目统一边界。

## 二、统一执行顺序

1. 保存原件，不覆盖源文件；记录格式、页数、版本、哈希和权限。
2. 建立 PDF 物理页、论文页、章节、表图和附件的证据定位基线。
3. 提取来源总卡与元数据；不确定字段保持待核验。
4. 为每个源文件单独生成 `材料简称_引用内容明细.md`；有引用时逐条记录引用方写的话，无引用时生成0条参考文献、0处引用事件的零引用说明。
5. 盘点材料实际呈现、作者声称、设计预期、研究应有和缺失的数据。
6. 建立变量与指标字典，审计样本、工具、处理、信效度和可复现性。
7. 建立主张—证据链，报告反例、限制与不支持的过度推论。
8. 建立数据缺口和可复用研究设计，不用推测填补缺失。
9. 结构化入库，并由第二遍独立回读或独立复核者直接查看原件签核。

## 三、逐文件引用内容明细强制门

> [!danger]
> 每个被分解的源文件都必须有一份独立的参考文献引用内容明细 Markdown 文件。该规则适用于论文、教案、课件、学习单、试卷、政策、课题附件及其他材料。批次汇总不能替代逐文件明细；缺少任意一份时不得宣布分解完成。

- 文件名：`材料简称_引用内容明细.md`。
- 默认位置：项目库 `30_研究资料/03_参考文献/引用映射/`；项目另有明确分类时服从项目规则。
- 有引用：逐条保存文后书目、位置、引用方写的话、引用方式、引用用途与被引原文核验状态。
- 无引用：仍须生成文件，写明"文后参考文献0条、正文引用事件0处"、检查范围和可能遗漏风险。
- 多文件批次：引用内容明细数量必须等于源文件数量。
- 引用方写的话不等于被引原文；未取得被引原文时必须明确标为未核验。
- 字段取值与结构按[[参考文献映射字段规范-Zcode版]]及项目内最新字段规范执行。

## 四、完成门

- [ ] 原件、来源卡、完整分解、数据资产、变量字典、方法审计、证据链和缺口均已建立。
- [ ] 每个源文件均有独立的参考文献引用内容明细；零引用文件也有0条/0处说明和检查范围。
- [ ] 有参考文献时完成内部引用映射；外部原文未核时明确声明。
- [ ] 学生数据匿名，原始数据不覆盖，处理后数据另存并留日志。
- [ ] 作者表述、原始事实和分析者解释没有混淆。
- [ ] 独立复核记录存在，高严重度表达问题已关闭。
- [ ] YAML、标签、索引、双链、JSON和敏感信息核验通过。
