# Flova眼镜店AI视频制作工作流

> [!abstract] 目标
> 以 Flova 作为项目级视频工作台，保存项目规格、脚本、分镜、素材、版本和时间线；以 Flova Agent 执行平台内任务，以 Skill 固化眼镜店制作规则，以 Codex/Zcode 负责外部编排、付费控制、模型调用、审计和归档。适用于WLC眼镜店15条脚本及后续系列短视频。

相关入口：[[眼镜店AI视频制作工作流-Zcode版]] · [[眼镜店AI视频脚本标准化工作流-Zcode版]] · [[眼镜店AI视频选题决策工作流-Zcode版]]

> 本工作流的完整版同时存放在 `WLC眼镜店运营知识库/20_Project/眼镜店AI视频/Flova眼镜店AI视频制作工作流.md`。此处为 Zcode 记忆库归档副本，源文件更新时同步本副本。

## 一、角色分工

| 组件 | 定位 | 负责 | 不负责 |
|---|---|---|---|
| Flova项目 | 单条视频的项目记忆 | 保存Final Video Spec、Docs、Storyboard、Media、Timeline和版本 | 不替代人工审批 |
| Flova Skill | 可复用制作手册 | 固定步骤、镜头规则、角色规则、物理规则、验收门槛 | 不保存本次视频的临时要求 |
| Flova Agent | 平台内执行者 | 分析素材、建立分镜、绑定媒体、推进时间线、局部修改 | 不得自行越过预算和审批关卡 |
| Codex/Zcode | 外部制片与导演 | 读制作包、拆任务、查模型与价格、调用MCP/API、保存task_id、审核、归档 | 不把自己当作视频渲染模型 |
| MiniMax-H3 | 当前正式视频渲染模型 | 按批准的关键帧和提示词生成镜头 | 不负责脚本、项目记忆和最终剪辑决策 |
| 人工验收 | 最终决策者 | 确认脚本、关键帧、预算、问题镜头和成片 | 不需要重复处理机械文件工作 |

> [!important] 当前模型边界
> Seedance 2.5 仅作为待接入候选模型，不写进正式生产依赖。Flova控制台未显示可用模型、参数和当次价格前，不得宣称已接入，更不得提交付费任务。当前MiniMax视频制作只允许使用`MiniMax-H3` V2接口。

## 二、一个视频对应一个Flova项目

每条选题建立一个独立项目，禁止把15条视频混在同一个时间线中。

项目名称：

```text
WLC_选题XX_简短标题_9x16_YYYYMMDD
```

项目内固定结构：

```text
Docs
├── 00_Final_Video_Spec
├── 01_创意简报与合规口径
├── 02_角色场景资产登记
├── 03_连续性与物理规则
├── 04_正式脚本
├── 05_分镜与提示词
├── 06_预算与任务台账
├── 07_逐镜审核报告
└── 08_成片交付记录

Storyboard
├── Key Elements：大睿、小墨、门店、设备、镜架、品牌
├── Shots：逐镜动作、机位、对白、参考资产
└── Audio：大睿男声、小墨女声、BGM、环境声

Media Files
├── Anchors：上传锚点
├── Keyframes：批准关键帧
├── Clips：生成镜头及返修版本
├── Audio：人声、BGM、环境声
└── Delivery：字幕、封面、发布版

Timeline
└── 只放已通过审核的媒体版本
```

## 三、Final Video Spec模板

项目建立后先填写本规格；未确认前不得开始生成。

```yaml
project_id: WLC_选题XX
topic: 选题标题
content_type: 科普/避坑/探店/种草/品牌
platform_primary: 抖音
platform_secondary: [视频号, 小红书, 朋友圈]
aspect_ratio: "9:16"
duration_target_sec: 35
resolution_working: 768P
resolution_delivery: 768P或批准后的2K
fps: 25
language: zh-CN
cast:
  - role: 大睿
    visual_anchor: A01
    voice: Chinese (Mandarin)_Reliable_Executive
  - role: 小墨
    visual_anchor: A02
    voice: Chinese (Mandarin)_Mature_Woman
style_master: B01/B02/B03
scene_master: 门店场景编号
cta: 到店/私信/关注/收藏
budget_cap_cny: 待用户确认
render_provider: 待路由
render_model: 待核验
approval_owner: 用户
forbidden_claims:
  - 治疗近视
  - 恢复视力
  - 保证不涨度数
  - 100%有效
  - 全网最低
```

## 四、Flova眼镜店Skill核心规则

在Flova中创建或复制一个专用Skill，名称建议：

```text
WLC眼镜店短视频制片Skill
```

Skill必须包含以下长期规则。本次视频的标题、时长和临时文案仍写入Final Video Spec或Prompt，不写进Skill。

### 4.1 工作顺序

1. 读取Final Video Spec、制作包和资产登记。
2. 先输出执行计划，不立即生成媒体。
3. 完成事实与广告合规检查。
4. 锁定人物、造型、场景、声音和物理规则。
5. 生成Storyboard草案并暂停，等待分镜确认。
6. 只为高风险或核心镜头制作关键帧/小样。
7. 汇总模型、时长、分辨率、参考素材和预计费用，再暂停等待付费确认。
8. 获批后逐镜生成；每次任务保存task_id，禁止重复提交。
9. 逐镜审核后只把“通过”版本绑定到Timeline。
10. 统一制作人声、音乐、字幕和成片，不使用各镜头自带的碎片人声和音乐。
11. 输出成片、字幕、封面、审核报告、任务台账和成本记录。

### 4.2 人物与声音

| 角色 | 身份来源 | 默认站位 | 固定声音 | 表演要求 |
|---|---|---|---|---|
| 大睿 | A01唯一身份锚点 | 双人镜头左侧 | `Chinese (Mandarin)_Reliable_Executive`男声 | 专业、自然、有节奏，不端着 |
| 小墨 | A02唯一身份锚点 | 双人镜头右侧 | `Chinese (Mandarin)_Mature_Woman`女声 | 亲和、自然，长句先压缩文案 |

- 双人母版B01/B02/B03只控制造型、站位和氛围，不能替代A01/A02身份锚点。
- 双人镜头中两张脸、上半身和主要手势必须清楚；禁止混脸、换位、复制人物或生成第三人。
- 对话使用正面或前侧45度开放式双人中景；禁止用顾客后脑勺、肩膀、虚化前景或商品遮住角色。
- 每个镜头只有一个主要动作；动作按“起势—执行—落点—余韵”设计，使用自然1倍速。
- 表情不能冻结。角色说话时有轻微口型、手势和视线变化；倾听者有自然呼吸、眨眼、轻点头或微笑。
- 大睿、小墨对白分段生成，不能同一句叠声，不能交换音色。

### 4.3 门店、设备和品牌

- 只使用门店场景资产清单中批准的门店场景。
- 验光仪、座椅、服务台、柜体、品牌墙均为固定刚体；人物不得搬、推、拖、抬或旋转。
- 提示词明确“设备从首帧到尾帧完全固定，不移动哪怕几厘米”。
- 门店使用5000–5500K中性白，禁止整体黄滤镜、肤色漂移和相邻镜头无理由冷暖跳变。
- 模型不得生成可读处方、检测数值、价格、地址、电话、Logo或新品牌文字；全部使用后期叠加的审核文字层。
- 镜面和镜片必须检查反射方向、人物数量和空间一致性。

### 4.4 镜架与手部物理

- 松散镜架为高风险道具。非必要不拿镜架，优先空手示意或触碰自己佩戴的固定眼镜。
- 禁止镜架摆动、软化、拉伸、漂浮、穿脸、镜腿错接、铰链变化、重复镜框和镜片凭空增减。
- 检查镜架时优先使用固定首帧：镜架平放、双手不接触，只允许眼睛和头部轻微运动。
- 必须拿镜架时拆成短镜头，采用实拍、静帧轻动效或首尾帧约束；禁止连续完成“拿起—旋转—检查—放下”。
- 手指、镜腿、鼻托和镜片边缘必须按2fps制作接触表检查。

### 4.5 医学与广告合规

- 不把眼镜、镜片或验光描述为疾病治疗手段。
- 产品参数、折射率、材料、品牌型号和医学结论必须有可核验来源；无法核实时标记“待核验”，不补写。
- 不承诺度数控制结果，不使用绝对化、最低价和保证性语言。
- 画面中的检查动作不能冒充医疗诊断；CTA使用“到店检查、专业验配、根据个人情况选择”等稳健表述。

原始4K资产只用于本地生成准备和验收，不直接上传公开仓库或平台：

```text

```

### 5.2 平台上传锚点

Flova、云端API和GitHub只使用一一对应的小体积上传锚点：

```text
/Users/wangzirui/眼镜店AI视频/attachments/上传锚点/人物锚点/家庭数字人_4K/
/Users/wangzirui/眼镜店AI视频/attachments/上传锚点/场景锚点/门店数字母版_4K/
```

### 5.3 资产登记表

|---|---|---|---|---|
| A01 | 大睿身份 | 脸型、五官、人物辨识 | 背景、旧服装、偏色 | Key Element身份参考 |
| A02 | 小墨身份 | 脸型、五官、人物辨识 | 背景、旧服装、偏色 | Key Element身份参考 |
| B01/B02/B03 | 双人造型 | 服装、站位、整体关系 | 替代身份、混脸 | Style/Composition参考 |

## 六、逐镜分镜数据标准

每个Storyboard Shot至少包含：

| 字段 | 要求 |
|---|---|
| `shot_id` | S01、S02……唯一编号 |
| `duration_sec` | 服从动作时长，不为凑固定时长拖慢动作 |
| `narrative_function` | 钩子、解释、演示、证明、CTA等 |
| `cast` | 大睿/小墨/双人/纯场景 |
| `dialogue` | 角色、台词、预计语速与时间段 |
| `continuity_in` | 承接上一镜的身份、位置、动作和道具状态 |
| `space_state` | 人物站位、设备、桌面和道具位置 |
| `camera_setup` | 景别、机位高度、方位、焦段、距离、运镜速度 |
| `main_action` | 唯一主要动作及逐秒动作节点 |
| `continuity_out` | 留给下一镜的结束状态 |
| `transition_to_next` | 动作、视线、构图或声音匹配依据 |
| `references` | A01/A02、造型母版、场景、首尾帧 |
| `physics_lock` | 固定刚体、接触、遮挡、反射和物体恒存规则 |
| `negative_constraints` | 混脸、第三人、慢动作、僵硬、穿模、乱码等 |
| `risk_level` | 低/中/高，高风险镜头先做小样 |
| `approval_status` | 草稿/待确认/已批准/需修/废弃 |

## 七、十三阶段执行流程

### Gate 0：项目预检

- 按15条脚本总览与制作顺序选择下一条，不按编号盲做。
- 读取对应制作包、锚点配置、场景清单和handoff。
- 检查Flova当前账户、积分、可用模型、导出能力和Agent接入状态。
- Codex/Zcode执行只读检查，不上传、不生成、不扣费。

**通过条件：** 输入文件齐全，下一条选题明确，未发现密钥或隐私文件准备上传。

### Gate 1：创意简报与合规

- 明确目标受众、核心信息、首3秒钩子、情绪弧线、CTA和平台。
- 核对品牌、产品和医学事实；不确定内容移入待核验清单。
- Flova Agent先输出计划，不生成媒体。

**通过条件：** 用户确认核心文案和禁用表达。

### Gate 2：项目规格冻结

- 填写Final Video Spec。
- 锁定大睿/小墨、造型母版、门店场景、画幅、时长、声音和工作分辨率。
- 记录版本号，例如`spec_v1`；后续修改产生新版本，不覆盖历史。

**通过条件：** 所有不可变项明确，无“模型自行发挥”的关键空白。

### Gate 3：Storyboard与连续性

- 按第六章字段创建逐镜分镜。
- 双人对话优先同框开放式中景，避免正反打造成身份和空间漂移。
- 高风险镜架、手部、设备、镜面和多人互动镜头单独标红。
- 检查总时长等于各镜头时长之和，台词能在镜头时间内自然说完。

**通过条件：** 用户确认Storyboard和逐镜提示词，全部镜头具备`continuity_in/out`。

### Gate 4：主关键帧与难镜小样

- 先制作一张批准主关键帧，锁定人物、服装、场景、白平衡、机位和品牌氛围。
- 先测试全片最难的一个高风险镜头，不先批量生成简单镜头。
- 主关键帧或难镜失败时只修改分镜、参考资产或提示词，不进入批量渲染。

**通过条件：** 身份、空间、物理规则和构图均通过。

### Gate 5：模型路由与预算确认

正式提交前输出：

| 镜头 | 模型/入口 | 时长 | 分辨率 | 输入素材 | 预计费用 | 风险 |
|---|---|---:|---|---|---:|---|
| SXX | 待核验 | X秒 | 768P/2K | 图片/视频/音频 | ¥X.XX | 中/高 |

- Flova平台内生成：以控制台当次模型、规格和积分为准。
- 外部生成：当前MiniMax只用`MiniMax-H3` V2接口，先768P验证。
- 预算确认只覆盖列出的任务；返修和升档必须重新确认。
- 不得自动从订阅切到PayGo、积分或其他供应商。

**通过条件：** 用户明确确认模型、任务数和预算上限。

### Gate 6：逐镜生成与任务记录

每个镜头执行一次：

```text
提交一次 → 立即保存task_id → 只轮询原任务 → 成功后立即下载 → 校验文件 → 登记Flova媒体版本
```

- 网络慢、状态未知或临时超时不等于失败，禁止重复创建任务。
- 保存模型、参数、参考资产、提示词、任务ID、预计/实际费用和本地路径。
- Flova中的媒体命名：`SXX_V01_模型_分辨率_状态`。

### Gate 7：逐镜审核

每个镜头抽取首帧、中帧、尾帧；高风险接触镜头制作2fps检查表。

审核结论只允许：

- `通过`：可绑定Timeline。
- `需修`：列出具体时间点和修复方案。
- `废弃`：保留文件和任务记录，不进入Timeline。

重点检查：身份、遮挡、动作速度、表情、手指、镜架、固定设备、文字、Logo、反射、阴影和相邻镜头连续性。

### Gate 8：镜头级返工

- 只重做问题镜头，已经通过的媒体版本继续沿用。
- 返工前先判断能否通过剪短、静帧、后期文字、局部编辑或替换剪辑点解决。
- 需要新付费生成时重新提交费用表并取得确认。
- 新版本使用`V02/V03`递增，禁止覆盖旧版。

### Gate 9：声音制作

- 大睿男声、小墨女声，按角色和镜头分段生成，再合成连续人声母轨。
- 不采用H3或其他视频模型逐镜生成的碎片对白。
- 最终字幕逐字匹配最终人声；小墨长句优先缩短文案，再考虑约1.10–1.35倍本地调速。
- 整片只使用一条连续BGM；人声出现时自动压低音乐。

### Gate 10：Timeline组装

- Timeline只使用标记“通过”的镜头版本。
- 先完成无声视觉粗剪，确认节奏与连续性；再加入人声、环境声、BGM和字幕。
- 对需要精修的单镜头在左侧局部编辑，不让Agent重新生成整条片。
- 若Flova导出后还需精修，可导出PR/Jianying/CapCut/Final Cut工程继续处理。

### Gate 11：粗剪与成片验收

- 正常速度完整观看一次，再对高风险镜头逐帧检查。
- 制作相邻剪辑点“上一镜尾帧+下一镜首帧”对照。
- 音频目标约`-16 LUFS`，真峰值不高于`-1.5 dBFS`。
- 字幕最多两行，避开平台按钮区；检查乱码、错误数字、变形Logo和模型水印。

### Gate 12：导出、归档与复盘

至少交付：

```text
高质量母版
平台发布版
无字幕版
SRT字幕
封面
连续人声母轨
BGM/最终混音
逐镜审核报告
任务ID与成本台账
Final Video Spec与Skill版本
```

- 临时生成链接失效前完成本地下载。
- 对外仓库只推送差异文件和允许公开的小体积上传锚点，不推送4K原始锚点、API Key或临时下载URL。
- 发布后记录3秒留存、完播率、互动率、私信/到店转化和评论问题，把可复用改进写回Skill。

## 八、Flova与外部模型的两条生产路径

### 路径A：Flova平台内生成

适用条件：Flova已提供合适模型，参数满足镜头要求，费用已核实并获批。

```text
Codex/Zcode建立项目与规格
→ Flova Agent创建Storyboard
→ 用户确认
→ Flova生成关键帧/镜头
→ 逐镜审核与版本选择
→ Timeline组装
→ 导出
```
