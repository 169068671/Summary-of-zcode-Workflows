# 用户长期偏好

> [!important] 记录原则
> 只保存用户已明确确认、能跨项目复用的偏好。

## 沟通

- 默认使用中文。
- 先给结果，再补充必要说明。
- 执行中需要简短告知进度，不让任务长时间无反馈。
- 面向用户的交付尽量非技术化，但在调试或核对时保留必要技术证据。

## 执行

- 对已确认的任务主动执行并完成验证。
- 涉及新的付费调用时，先核对模型、参数、余额和预计成本；避免网络慢造成重复提交。
- 对已提交的异步任务保存任务 ID，只轮询原任务。
- 交付文件时提供可点击的本地路径。
- **音频转写文件和原始音频文件必须归档到对应单元/项目目录下**（如 `转写归档/`、`音频归档/` 子目录），绝不能留在桌面。转写完成后立即归档，不依赖用户提醒。
- **图片理解必须使用 MCP 工具**（`mcp__MiniMaxCodingPlan__understand_image`），不用内置视觉能力。遇到需要识别、分析图片内容的任务，一律调用该 MCP 工具完成。
- **手写答题图片的空白勾选框可能被误判为已勾选**（2026-08-18 大睿 09 闭卷批改发现）。批改试卷时以实际答题文字内容为准，不依赖识别出的勾选符号；涉及「关键错误检查」勾选栏时特别留意，必要时向用户确认。
- **不使用子智能体（Agent）创建或修改项目文件**：子智能体生成内容质量不可控（直接复制源文件不按标准改、漏改口述/留空等），执行过程不可见。所有文件创建/修改直接用 Write/Edit 自己完成，不用 Agent。

## Git 推送

- GitHub 与 Gitee 统一使用 SSH；不得在 remote URL、命令、日志或笔记中保存访问令牌。
- 默认使用 `dual-git-ssh-sync` Skill/MCP，先 fetch 和复查差异，再经用户确认执行增量推送。
- 禁止 force push、reset、删除分支或覆盖远端独有提交；远端分叉时停止并单独处理。
- 已经存在于远端且内容未变化的文件不重复上传；工作区有改动时先生成文件级复查表，只暂存批准路径。
- GitHub LFS 完整版与 Gitee 普通文件/精简版允许保留不同历史；Gitee 出现 LFS 指针时默认停止，不使用 `GIT_LFS_SKIP_PUSH`。
- 默认推送 `main` 分支，保留仓库已有 upstream 设置，明确向两个 remote 推送而不静默改跟踪关系。
- 推送时使用北京时间，并在完成后核验两个远端的 ahead/behind 状态。

## PDF 生成（pandoc + xelatex）

- 生成合集 PDF 时用 `pandoc --pdf-engine=xelatex`，字体用 `-V mainfont="STSong" -V CJKmainfont="STSong" -V monofont="Menlo"`。
- **STSong 不支持以下 Unicode 字符**，生成前必须预处理替换，否则报 Missing character 警告或 LaTeX 编译失败：
  - 下标：₂→2、₃→3、₄→4
  - 上标：²→2、³→3、⁺→+、⁻→-
  - 箭头：↑→上箭头、↓→下箭头、→→->、←→<-
  - 符号：△→三角形、≈→约等于
  - Emoji/勾叉：✅→√、❌→×、✗→×、✓→√、⚠️→[!]、🔴→!、🔔→[铃]
  - **00-07/0809 专用脚本**（`99_System/gen_unit_pdf_0007_xelatex.py`、`gen_unit_pdf_0809_xelatex.py`）用 PingFang SC 字体，`clean_markdown` 已实现上述全部 emoji 替换（2026-08-18 扩展，含 ✓🔴🔔⚠️）；数学模式中文（如下标 `_{溶质}`）须用 `\text{}` 包裹，否则 xelatex 缺字。新单元优先用脚本（PingFang SC，已验证），STSong 规则为早期通用记录。
  - **不要用 `\uparrow` 等 LaTeX 命令替换**——pandoc Markdown 正文里会被当纯文本传给 LaTeX 导致 Undefined control sequence。用中文词（上箭头/下箭头）或纯文本替代。
- 不要用 `--highlight-style` 参数（pandoc 3.9 已废弃，改用 `--syntax-highlighting`，或直接省略）。
- LaTeX 版本警告（`requested release 2026/06/01 but only 2025/11/01`）是 TeXLive 发行版问题，不影响输出，无法在命令行消除，可忽略。
- 合集 PDF 带封面页：用 YAML frontmatter（title/subtitle/date）+ `\newpage` 分隔封面和正文。
- **合并多个 Markdown 文件时，必须去掉后续文件的 YAML frontmatter**（只保留封面文件的 frontmatter）。否则后续文件的 `title:` 会覆盖封面标题（如 09小墨答案的 `title: 09小墨答案_…` 把家长封面变成了小墨）。用 Python 脚本去掉 `---` 包裹的头部。
- 合集 PDF 分三份：
  - **大睿**：08汇总卡（大睿拆分版）+ 08大睿提纲 + 09大睿闭卷
  - **小墨**：08汇总卡（小墨拆分版）+ 08小墨提纲 + 09小墨闭卷
  - **家长**：00附家长指南 + 09大睿答案 + 09小墨答案（不含 08 提纲）
- 08 汇总卡是两人合在一起的文件，生成合集时需拆分出大睿部分和小墨部分分别放入各人合集。
- **09 闭卷试卷必须留出答题空间**：每道题后加 2-3 行下划线（`___`），填空题留空格，简答题留 2-3 行，计算题留完整解题区。不能只列题目不留写的地方。
